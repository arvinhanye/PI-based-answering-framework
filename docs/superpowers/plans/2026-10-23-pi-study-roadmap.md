## 3. P0：直接提升日常刷题

可以并行开发。§3.3 依赖 §3.2 的标签。

### 3.1 进度与成绩页

**目标**：用户随时能看到“做到哪了、哪里弱”。

- `/study menu` 里的“成绩”改成一张卡片，例如：

  ```
  进度
  1500题　已做 312 / 1508　正确率 78%
  省赛　　已做 0 / 109
  PDF　　 已做 0 / 979

  错题 41 · 今天到期复习 12
  距比赛 21 天                  ← 设置了比赛日期才显示

  考点正确率（已做 ≥ 5 题的考点）
  WLAN 82% · 路由 65% · 安全 71% ……
  ```

- 新增 `/study stats` 直接显示这张卡片。
- 正确率只算独立作答、可计分的最新一次作答，沿用现有统计口径；辅助作答单独一行显示，不混入。
- 考点一行在 §3.2 完成前只显示有标签的考点。
- CLI 的 `stats` 输出同样的文字版本。

**验收**：做几题后，卡片上的已做题数、正确率、错题数与数据库一致；不出现 JSON、英文字段名或“numerator / denominator”字样。

### 3.2 补全考点标签

**目标**：让按考点统计和薄弱点选题有数据可用。

1. **先定分类表**：根据华为 ICT 网络赛道的范围拟一份 10–15 个考点的分类表，例如 WLAN、路由、交换、安全、IP 基础、QoS、网络管理、SDN 与自动化等，以实际题目内容为准。**拿给用户确认后再打标签**。分类表放在配置文件里，可以修改。
2. **试跑**：先抽 50 题打标签，把结果给用户抽查。
3. **全量**：每批 20 题左右调用 `deepseek-flash`（关闭思考），只发送题干和选项，不发送答案。估算全量约 1–2 元：输入约 50 万 token、输出约 3 万 token。发送前显示题数和预估费用，用户确认一次后开始。费用计入月度账本。
4. **存储**：模型给出的标签标记为“模型建议”，与来源自带的标签（例如【无线考点】）分开保存；来源标签优先，不覆盖。支持断点续跑，重复运行不会重复收费。
5. **入口**：CLI `study tag plan`（显示分类表和预估费用）、`study tag run`。不需要 Pi 入口。
6. 界面上不显示“未分类”；没有标签的题，卡片标题直接省略考点。

**验收**：全量完成后，“未分类”占比低于 5%；随机抽 30 题人工检查，标签明显错误的不超过 3 题；账本记录的费用与预估相差不超过一倍。

### 3.3 薄弱考点选题

**目标**：完成 R07 中“薄弱点”的部分。

- `/study 考点 WLAN`：只出这个考点的题，可以和来源组合，例如 `/study pdf 考点 WLAN`。
- `/study 薄弱`：从正确率最低的 3 个考点出题（只算已做 ≥ 5 题的考点），优先出这些考点里没做过的题和错题。
- 默认队列（不带参数的 `/study`）在现有“每 4 道复习插 1 道新题”的基础上调整：新题优先从薄弱考点里选。还没有足够作答数据时，按原题号顺序出题。
- 有争议或不计分的题不参与正确率计算，沿用现有规则。
- 考点名支持模糊匹配，例如 `wlan`、`无线` 都能匹配到 WLAN。匹配不到时列出可用的考点。

**验收**：构造一组作答数据后，`/study 薄弱` 出的题属于正确率最低的考点；`/study 考点 xxx` 只出该考点的题。

## 4. P1：备考价值高

**建议在用户试用 3–5 天、攒下一批真实反馈之后再开工。** 先处理反馈中的体验问题，再做本节。

### 4.1 测验模式

**目标**：限时模拟考试。

- `/study 测验`：按配置抽一套题，开始计时。答题方式与快刷相同（直接输入答案），但**交卷前不显示对错和解析**；输入 `n` 进入下一题，可以输入题号回到前面的题修改。
- 常驻提示行显示剩余时间和已答题数。时间到了自动交卷（这是唯一不需要用户操作的提交，因为是考试规则）。也可以用 `/study 交卷` 提前交卷。
- 交卷后显示成绩卡：总分、各题型得分、用时、错题列表；输入错题编号可以查看解析或问 DeepSeek。错题进入复习队列。
- 测验中允许问 DeepSeek，但这道题记为辅助，并且不计入测验成绩。提问前在常驻提示行注明这一点，不弹确认框。
- 测验期间退出 Pi 后，再次 `/study` 回到这场测验，计时按实际流逝的时间计算。
- **需要用户提供**：比赛的题型构成、题量、时长和计分规则。在拿到之前，用配置文件里的默认值占位（例如 60 题、60 分钟、单选 1 分、多选 2 分、判断 1 分），交付时列出这些占位值。

**验收**：完成一场缩短为 5 题、2 分钟的测验，覆盖提前交卷和超时自动交卷；交卷前任何界面都看不到答案；成绩卡分数与逐题结果一致。

### 4.2 联网查证改为 DeepSeek 工具

**目标**：完成 R09 / R14 / R15 中最有用的部分：题库答案可疑时，能查官方资料。

- 在学习态注册一个模型可调用的工具 `search_docs`，复用 `src/evidence/` 中的 Search / Fetch 和来源白名单（华为官方文档、RFC 等）。
- 触发方式：用户说“查一下官方文档”这类话，或者模型认为题库答案与自己的判断冲突时，由 DeepSeek 自己调用。不需要单独的菜单或命令。
- 每次提问最多 2 次 Search、3 次 Fetch（沿用原方案默认值）；费用计入月度账本。
- 回答中给出引用的标题和链接。**查证结果不修改题库答案，也不改分**，只在对话中说明。
- 作答前提问时，工具同样可用，但遵守“尽量不直接说出答案”的提示词约束。
- 证据缓存暂不做；同一题重复查证就重新查。

**验收**：选一道答案有争议的题，问“查一下华为官方文档”，回答附带可打开的官方链接；账本中记录了 Search / Fetch 费用；分数没有变化。

## 5. P2：有需要再做

本节不主动开工，等用户提出时再做。

### 5.1 重复题合并

- 只合并题干、选项集合、答案三者在规范化后完全一致的题；题干相同但选项不同的不合并。
- 合并后同一题只出一次、统计只计一次，卡片上显示所有出处，例如“1500题 第 12 题 / PDF p5-q23”。
- 不改动导入数据，合并关系单独存一张表，可以撤销。
- 当前只影响约 4% 的题（§1）。

### 5.2 新资料导入

- 用户拿到新题库（例如国赛资料）时，为那份资料单独写转换脚本，输出标准 JSON 后用现有 `study import` 导入。沿用现有三份资料的做法：先抽样人工核对，再全量导入。
- 不做通用导入作业、导入模板或导入界面。

### 5.3 Pi 里的备份入口

- 新增 `/study backup`，调用现有备份服务，备份到默认目录，完成后显示文件路径和大小。恢复仍然只在 CLI 中进行。
