## 0. 给实现方的话

用户试用 0.1.0 MVP 后的反馈是“使用体验极差”：答一道题要走好几层菜单和确认框；想让 DeepSeek 讲解要层层嵌套，讲完还不能追问。用户的原话是：重心应放在使用体验上，而不是为了判分的严谨性忽视用户感受。

本文的决定**优先于原设计方案中与之冲突的条款**，尤其是：

- R05 / §6 的“一次性提交凭据 + 确认框”提交流程；
- R17 / §9 的“受控 provider + 发送前预算准入 + 预留状态机”；
- §10.1 的 10 个模型工具。

实现时请遵守三条原则：

1. **不要加回确认框。** 唯一的后悔药是 `/study undo`。
2. **不要为严谨性增加用户操作步数。** 需要记录的状态（辅助作答、不确定等）都应该从用户的自然输入里推断出来。
3. **用户界面上不出现内部术语**，例如 `source_only`、`presentationId`、`参考判分`、`nano`、UUID。

验收标准第一条（§9）是：**在 Pi 中答一道选择题 = 输入答案并回车；进入下一题 = 输入 `n` 并回车。**

## 2. 命令与入口

| 输入 | 行为 |
| --- | --- |
| `/study` | 有进行中的会话就直接显示当前题；没有就从全库开一轮新的。不弹菜单。第一次使用时问一次比赛日期（可跳过，见 §7.3） |
| `/study 1500`、`/study 省赛`、`/study pdf` | 按来源开新一轮。来源别名映射到现有 source id：`first-docx`、`province-docx`、`pdf` |
| `/study 错题` | 只出“答错过、且之后没有再独立答对”的题，不看复习日期。可组合：`/study 省赛 错题` |
| 任意入口后加 `随机` | 新题打乱顺序，例如 `/study 1500 随机` |
| `/study menu` | 一层菜单：切换题库、恢复旧会话、成绩、预算、比赛日期、答对自动下一题开关。没有子菜单 |
| `/study undo` | 撤销当前题的作答（§3.4） |
| `/study think` | 切换当前学习会话的 DeepSeek 思考模式，默认关闭 |
| `/study budget 20` | 直接把月上限改成 20 元，不弹确认框 |
| `/study exit` | 直接退出学习态，恢复原模型和工具，不弹确认框 |
| `n`、`下`、`Ctrl+N` | 下一题 |
| `Ctrl+O` | 用系统默认程序打开当前题的题图；多张时依次打开，或者打开第一张并提示数量 |

删除 `/study-answer`、`/study-exit` 两个命令。

“恢复旧会话”列表的每一行显示 `来源 · 开始时间 · 已做 N 题`，不显示 UUID。

## 3. 输入判定

学习态下，用户提交的每一行（非 `/` 命令）按顺序判定：

1. `n` 或 `下` → 下一题。
2. 符合当前题型的作答格式 → 判分（§3.1）。
3. 看起来像作答但不合法 → 不判分，提示原因（§3.2）。
4. 其他 → 作为提问发给 DeepSeek（§5）。

原则：**模糊输入宁可当提问，也不要误判分。**

### 3.1 作答格式

先去掉首尾空白；再去掉可选前缀 `选`、`选择`、`答案`、`答案是`、`我选`；最后去掉末尾的 `?` 或 `？`（有的话记为“不确定”）。剩余部分：

| 题型 | 合法作答 | 规范化 |
| --- | --- | --- |
| 单选 | 恰好一个选项字母，大小写均可 | 大写 |
| 多选 | 一个或多个选项字母，可用空格、`,`、`，`、`、` 分隔，例如 `AC`、`a c`、`A,C` | 大写、去重、排序 |
| 判断 | `对 / 错 / √ / × / 正确 / 错误 / T / F / A / B`，大小写均可 | `true` / `false` |
| 填空 | 以 `=` 开头，`=` 之后为答案；多空用 `\|` 分隔 | 保留大小写和内部空格（沿用现有填空规则） |

例子：`B` 判分；`选B` 判分；`AC?` 判分且记为不确定；`B为什么不对` 当提问；`什么是 Mesh` 当提问；填空题输入 `display ip routing-table`（没有 `=`）当提问。

### 3.2 看起来像作答但不合法

整行由字母、分隔符和前缀组成，但：

- 包含当前题不存在的选项字母；
- 单选题给了多个字母；
- 判断题给了 `C` 这类字母。

这时**不判分，也不发给 DeepSeek**，只提示一句，例如“这题是单选，只能选一个”“这题只有 A–D”。

### 3.3 判分后的记录

- 默认把握程度为“确定”；带 `?` 为“不确定”。
- 在本题作答前问过 DeepSeek → 记为辅助作答。
- 仍然使用现有的提交事务和幂等键，保证重复回车不重复计分；但**不再需要一次性凭据、菜单来源校验或确认框**。可信来源的判断只保留一条：作答只能来自用户在学习态下的真实输入（`input` 事件）或 CLI，不注册任何模型可调用的作答工具。

### 3.4 撤销

`/study undo` 只对当前题有效，在输入 `n` 之前可用。原记录标记为作废，不计入任何统计，然后可以重新作答。已经进入下一题时提示“只能撤销当前题”。

## 4. 卡片

题目和结果都用 `pi.sendMessage()` 加自定义消息渲染器显示，**留在对话区里，不用 `notify`**。这些消息不进入模型上下文；模型需要的题目信息按 §5.2 单独注入。

### 4.1 题目卡片

```
第 37 题 · 单选 · 无线考点 · 1500题      本轮 8/10 ✓
以下哪条命令在配置 Mesh 白名单时不是必须用到的？
A. radio radio-id
B. ap-system-profile
C. mesh-whitelist-profile
D. peer-ap mac
📎 1 张题图，Ctrl+O 打开
输入答案，或直接打字问 DeepSeek（本月已用 0.12 / 10 元）
```

- “第 37 题”使用原题号（`sourceKey`），不使用会话内序号。
- 没有考点标签时不显示这一段，不要写“未分类”。
- “本轮 8/10 ✓”是本次会话内已判分题的正确数 / 判分数。
- 这题有资料问题（`needs_review`）时加一行：`⚠ 这题资料有问题，可以练但不计分`。

### 4.2 结果卡片

答错：

```
✗ 错误　你选 B，正确答案 D
解析：……（题库原文，完整显示）
⚠ 资料提示：……（仅当这题有已知问题时显示）
n 下一题 · 直接打字问 DeepSeek（本月已用 0.12 / 10 元）
```

答对时第一行为 `✓ 正确　答案 D`，解析同样默认展开。

- 多选题加一行：`漏选 C · 多选 E`（只显示非空项）。
- 题库没有解析时显示 `题库未提供解析`，不显示空行。
- 不可评分的题显示 `这题资料有问题，本次不计分　题库答案：D`。
- 卡片上不出现“参考判分”“依据来源答案”“source_only”“辅助作答”等字样。辅助、不确定只影响复习安排和成绩页，不在卡片上提示。

### 4.3 答对自动下一题

`/study menu` 中可开关，默认关闭。开启后，答对时显示结果卡片并紧接着显示下一题卡片；答错照常停下。

## 5. DeepSeek 对话

### 5.1 通道

- 进入学习态时，把模型切到 Pi 内置的 `deepseek/deepseek-flash`，并关闭学习态不需要的工具（文件、bash 等）。退出时恢复原模型和工具（沿用 `ControlledSession` 的保存与恢复逻辑）。
- 用户的提问就是一次普通的 Pi 对话：流式输出、Markdown 渲染、连续追问都由 Pi 原生负责。
- **删除离线桩 provider**（`study-offline/local-quick`）。
- 凭证沿用 Pi 的 DeepSeek 凭证（`/login` 或 `DEEPSEEK_API_KEY`）。没有凭证时，提问不发送，只在本地提示一句“未配置 DeepSeek，答题不受影响，配置方法：……”。
- 学习态下用户手动切到其他模型时，沿用现有行为：退出学习态并提示。

### 5.2 自动附带的题目上下文

每次提问发送前（`before_agent_start` 或 `context`），注入一段“当前题”上下文：

- 题干、选项、题型、考点；
- 题图：如果 §1 的待验证项通过，作为图片附上；未通过就写明“有 N 张题图未发送”，让模型不要假装看过图；
- 作答状态：
  - **已作答**：你的作答、对错、题库答案、题库解析、资料提示；
  - **未作答**：不附答案和解析，并加一条指令“用户还没有作答，引导思考，尽量不要直接说出答案；用户明确要求答案时可以说”。

系统提示词保留现有讲解提示词的核心要求：区分题库说法与模型推断；资料有冲突时直说；不执行教材里的命令。去掉“不能声称已检索”“不能改动用户分数”这类面向旧架构的条款。回答用简洁中文。

### 5.3 换题时的上下文

进入下一题后，上一题的提问和回答**不再发给模型**，只留在屏幕上。推荐用 `context` 事件过滤：只保留当前题开始之后的消息。如果 §1 的验证不通过，退路是在换题时开一个新的 Pi 会话分支，选哪种请在实现记录里说明。

### 5.4 思考模式

默认关闭，`/study think` 切换。卡片底部或状态栏用一个小标记提示当前已开启思考模式。

## 6. 预算（软记账）

- 每次学习态请求结束后，从 Pi 返回的 usage（输入、缓存命中、输出 token）按人民币费率换算并记账。费率放在配置里，**不设过期时间**。初始值：输入 2 元、缓存命中 0.04 元、输出 8 元，每百万 token，与原 `profiles.ts` 一致。
- 本月用量达到上限的 80% 时提示一次。达到 100% 后，提问不再发送，只提示“本月 DeepSeek 额度已用完，可用 `/study budget` 调整”。本地答题不受影响。
- 只统计学习态内的请求，退出学习后的普通对话不计入。
- 自然月、Pi 与 CLI 共用同一个账本，这两点保留；可以复用现有 `finance.sqlite`，但只需要“按月累计已用金额”这一张表。
- **删除**：预留、`dispatched / unknown / released` 状态、24 小时费率卡、payload 摘要校验、费率下限校验、完整上下文保守预留。
- 文档写明：这是软上限，最后一笔请求可能让用量超出几分钱；真正的硬上限是 DeepSeek 账户的预付余额。

## 7. 出题顺序

### 7.1 队列

1. 先出到期的复习题和错题：答错的、带 `?` 的、作答前问过 DeepSeek 的。每 4 道复习题插 1 道新题（沿用现有规则）。
2. 新题默认按原题号顺序；带 `随机` 时打乱。
3. 不指定来源的 `/study` 按 1500 题 → 省赛 → PDF 依次出新题。
4. `/study 错题` 只出错题集合，不插新题。

### 7.2 复习间隔

沿用现有的 1 / 3 / 7 / 14 / 30 天以及“错误、不确定、辅助一律次日复习”的规则。设置了比赛日期时，间隔不超过离比赛的剩余天数（现有 `scheduler.ts` 已有 `examDate` 逻辑，确认它在这条新路径上生效）。

### 7.3 比赛日期

第一次输入 `/study` 时问一次（可以直接跳过），之后在 `/study menu` 里修改。不要像旧版那样默认填一个日期。

## 9. 验收标准

按以下清单逐项验收，并在 `pi-study/docs/acceptance/` 下记录真实 Pi 终端的操作结果：

1. 在 Pi 中输入 `/study`，直接看到题目卡片，没有菜单。
2. 输入 `B` 回车，立即看到结果卡片：没有输入框、没有把握程度选择、没有确认框。
3. 输入 `n` 回车（以及按 `Ctrl+N`），看到下一题卡片。
4. 多选题输入 `ac`、`A,C`、`选AC` 都能正确判分；单选题输入 `AB` 只提示不判分；输入 `B为什么不对` 会发给 DeepSeek。
